# Контекст проекта: Zapret TV & Mobile Bridge

## 1. Назначение и концепция проекта
Zapret TV & Mobile Bridge — это готовое коробочное решение на Python для Windows, выступающее в роли локального домашнего сетевого шлюза, HTTP/PAC-прокси и Telegram MTProto-моста для Smart TV (LG webOS, Samsung Tizen, Android TV, Google TV, Apple TV) и мобильных устройств (iOS / iPadOS / Android).

Шлюз связывает домашние устройства в одной Wi-Fi сети с локально работающим на Windows-компьютере сервисом **Zapret** (десинхронизация DPI через драйвер WinDivert), позволяя смарт-телевизорам и смартфонам смотреть YouTube в 4K без буферизации и ускорять работу сервисов без установки сторонних VPN на сами устройства.

## 2. Архитектура и структура файлов

```text
D:\projects\zapret-tv-bridge\
├── service.bat               # ЕДИНСТВЕННЫЙ файл в корне для настройки и управления (TUI в стиле Zapret)
├── bin\                      # Автономные бинарные файлы (Zero-Python standalone runtime)
│   └── ZapretTVBridge.exe    # Скомпилированное ядро моста со встроенным рантаймом и зависимостями
├── lists\                    # Списки доменов маршрутизации
│   ├── list-general.txt      # Домены для маршрутизации через Zapret (рандомизированы, дедуплицированы)
│   ├── list-general-user.txt # Пользовательские домены
│   ├── list-exclude.txt      # Домены прямого подключения (DIRECT: Яндекс, Сбер, Госуслуги, VK)
│   └── list-exclude-user.txt # Исключения пользователя (включая CloudCode / Google API)
├── supercell.mobileconfig    # DoT DNS-профиль для iOS (игры Brawl Stars и Clash Royale)
├── zapret_tv_bridge.py       # Исходный код ядра моста (HTTP CONNECT, DoH, PAC, In-Process TG)
├── tg_ws_proxy\              # Модуль Flowseal/tg-ws-proxy (Telegram MTProto WebSocket bridge, порт 1443)
├── requirements.txt          # Зависимости для запуска из исходного кода
├── README.md                 # Руководство пользователя (1 файл для настройки, без лишнего мусора)
├── LICENSE                   # Лицензия MIT
└── .gitignore                # Исключение временных логов, pid, ip, secrets, cache
```

## 3. Ключевые правила разработки и стандарты

1. **Zero Hardcode (Никакого хардкода)**:
   - **IP-адрес**: строго через динамическую функцию `get_local_ip()` (UDP-сокет к DNS + перебор частных адаптеров RFC1918 `192.168.x.x`, `10.x.x.x`, `172.16-31.x.x`). Запрещено жестко прописывать статические IP (например, `192.168.0.105`).
   - **Пути к файлам**: только относительные (`%~dp0` в .bat/.vbs и `os.path.dirname(os.path.abspath(__file__))` в Python). Никаких `C:\Users\...`.
   - **Поиск Python**: скрипты автоматически проверяют `PATH`, `py.exe`, реестр Windows (`HKCU`/`HKLM`), каталоги `%LOCALAPPDATA%\Programs\Python` и `%ProgramFiles%\Python`.

2. **Безопасность и политика открытого исходного кода (GitHub TOS)**:
   - **Нейтральная терминология**: в коде, логах, коммитах и документации строго запрещено использовать триггерные слова («обход блокировок», «реестр», «РКН», «Роскомнадзор», «цензура», «bypass»). Используется нейтральный термин: *Smart Routing / Локальный сетевой шлюз и прокси*.
   - **Удаление HAPP**: все упоминания и карточки приложения HAPP полностью исключены.
   - **Конфиденциальность**: личные данные, IP, временные файлы (`.pid`, `.ip`, `*.log`, `tg_secret.txt`) не отслеживаются в Git.

3. **Сетевые порты и логика работы**:
   - Порт `8080`: HTTP-прокси, раздача `http://<IP>:8080/proxy.pac`, профиля `supercell.mobileconfig` и статус-страницы `http://<IP>:8080/`. Автоподбор следующего свободного порта при конфликте.
   - Порт `1443`: Telegram MTProto WebSocket bridge (`Flowseal/tg-ws-proxy`) с поддержкой ключей `dd<secret>`.
   - Резолв доменов: для оптимизируемых медиа-сервисов (YouTube, Discord, Twitter/X) резолв выполняется через DoH (Cloudflare `1.1.1.1` / Google `dns.google`), защищая от подмены DNS провайдерами. Отечественные домены (список exclude) идут напрямую (`DIRECT`).

4. **Пользовательский интерфейс**:
   - Все исполняемые файлы пронумерованы `1_`, `2_`, `3_`... для интуитивного порядка в Проводнике Windows.
   - Описания должны быть простыми, понятными обычному пользователю без технического жаргона.

5. **Автоматическая синхронизация с GitHub**:
   - Удаленный репозиторий `origin` настроен с постоянным токеном авторизации.
   - Агент имеет право и возможность самостоятельно выполнять `git add`, `git commit` и `git push origin main` при внесении правок по запросу пользователя.
