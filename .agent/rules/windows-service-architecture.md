# Windows Service & Native CLI Architecture Rules

## 1. Режим запуска и удержание окна консоли
- При сборке нативных бинарников для Windows, объединяющих функции демона и менеджера:
  - Если передан флаг `--daemon`: процесс работает в тихом фоновом режиме без интерактивного ввода.
  - Если аргументы отсутствуют (`args.len() <= 1`) и поток ввода является терминалом (`is_stdin_terminal()`): открывать интерактивное меню управления.
  - При любых ошибках запуска в интерактивном режиме категорически запрещено немедленно вызывать `exit(1)`. Всегда выводить понятное диагностическое сообщение и вызывать ожидание нажатия клавиши (`pause_exit()`).

## 2. Регистрация служб Windows с длинными командными строками (>1024 символов)
- Никогда не передавать длинные цепочки аргументов (правила фильтрации, списки хостов) напрямую в аргумент `binPath=` утилиты `sc.exe`.
- Для надежной регистрации:
  1. Создать базовую запись службы через `sc.exe create <name> binPath= "%SystemRoot%\\System32\\cmd.exe" start= auto`.
  2. Записать полную строку параметров напрямую в реестр `HKLM\System\CurrentControlSet\Services\<name>\ImagePath` с типом `REG_EXPAND_SZ`.
  3. Обязательно вызывать `trim()` для исключения лидирующих пробелов, вызывающих ошибку Windows 87 (`The parameter is incorrect`).

## 3. Обновление запущенных исполняемых файлов в Windows
- Для безопасной перезаписи работающего бинарника использовать переименование:
  1. Переименовать запущенный файл в `<name>_old.exe`.
  2. Записать обновленный бинарник на место оригинального имени.
  3. Завершить старый процесс и удалить временный `_old.exe`.

## 4. Контроль занятости портов (AddrInUse)
- Проверять доступность портов 8080, 1080 и 1443 перед запуском слушателей.
- Если порт уже слушается существующим процессом, отображать статус `[RUNNING]` в менеджере вместо аварийного падения приложения.
